Análise de Dívida Técnica, UX e IA - Birth Hub 360

Relatório gerado a partir da documentação canônica do repositório.

1. Dívida Técnica e Arquitetural

Diagnóstico Principal (Clean Architecture Incompleta)

O sistema possui dois padrões arquiteturais coexistentes:

  • Módulos Migrados (Novo Padrão): activities, companies, contacts, crm, notes usam Clean Architecture (Domain, Application, Infra, Presentation).
  • Módulos Legados: ~23 módulos ainda acoplam regras de negócio à infraestrutura (chamadas diretas ao Prisma e APIs).

Anti-Patterns Identificados

  • Fat Components (UI + Lógica): 81 componentes React gerenciam ciclo de vida, chamadas de rede nativas (sem SWR/React Query) e estado localmente (ex: FloatingChatbook.tsx com 741 linhas).
  • God Services: Concentração de orquestração e infraestrutura. Exemplos críticos: bitrix.service.ts (856 linhas), enrichment.service.ts (840 linhas), gateway.ts (671 linhas).
  • Violação SOLID: Serviços dependem fortemente do PrismaClient concreto, dificultando testes isolados.

O Que Precisa Ser Consertado (Plano de Ação)

  • Refatoração Gradual: Extrair lógica de acesso a dados (Prisma) dos "God Services" para Repositórios.
  • Desacoplamento de UI: Adotar React Query (ou SWR) nos componentes para gerenciar cache e estado assíncrono, reduzindo os hooks useEffect complexos.
  • Inversão de Dependência: Padronizar o contêiner de injeção de dependências (atualmente rudimentar em src/shared/di/setup.ts).

2. Experiência do Usuário (UX) e Design System

Estética e Motion (Revenue Command Center)

A interface foi evoluída de um design "plano" para um ambiente com profundidade espacial focada em dados operacionais ("Do Sinal à Ação").

  • Design Tokens: Uso estrito do Tailwind CSS 4 com variáveis semânticas (--brand: #D4AF37, --surface, etc). Cores puras (black/white) e gradientes decorativos genéricos foram abandonados.
  • Profundidade e 3D: Implementação da regra dos 3 Planos (Ambiente, Superfície, Instrumento Elevado). O 3D (Three.js) é restrito a funções informativas vitais (ex: Signal Core 3D), sempre carregado via lazy-loading e com fallbacks 2D acessíveis.
  • Áudio Semântico: Os "bips" genéricos foram substituídos por sons significativos (sucesso, aviso, navegação), com controle do usuário para desativá-los no topbar.

O Que Precisa Ser Consertado / Monitorado

  • Evitar anti-patterns visuais descritos em memória (ex: animações "bouncy", bordas grossas SaaS genéricas).
  • Manter os gráficos com foco exploratório (drill-down, múltiplos comparativos) sem reduzir acessibilidade (teclado/descrição textual).

3. Motores de IA e Automação

Evolução da Arquitetura de IA

A fase atual erradicou funções simuladas ("mocks offline" com setTimeout) em favor de integrações reais via Clean Architecture.

  • Gateway Inteligente: A orquestração passa por um gateway central (LiteLLM / Groq / modelos locais via Ollama), documentado em gateway.ts.
  • Unificação de Agentes: O agente SDR foi unificado utilizando fluxo LangGraph autônomo (sdr.agent.ts), substituindo lógicas duplicadas.
  • Human-in-the-Loop (Compliance): Ações de impacto externo geradas pela IA (ex: disparar e-mail) nunca são executadas automaticamente. Elas são postadas em AIPendingAction para aprovação explícita do usuário.

O Que Precisa Ser Implementado / Revisado

  • Gestão de Erros e Custos: Garantir timeouts estritos e fallbacks configurados. O hub deve barrar fluxos RAG sem isolamento por tenant.
  • Auditoria de Automações: Toda execução de fila/automação (BullMQ) deve registrar Início, Fim, Erros e Retries. Nenhuma automação crítica pode sumir silenciosamente.

4. Agentes do Código (Swarm Orchestrator)

Governança de Agentes de IA Locais

O repositório adota um modelo de "Enxame" (Swarm) de engenheiros especialistas coordenados pelo Agente 00 (Coordenador).

  • Agent 00: Controla branches, concorrência e integração (Gateways).
  • Agent 01: Exclusivo para segurança, modelagem Prisma (Tenant RLS) e base de dados.
  • Agent 02: Dono da UI, rotas (App.tsx) e navegação.
  • Agent 06: Dono das integrações e extrações pesadas (ex: Bitrix).
  • Agent 07: Guardião do RAG, filas, automação, LangGraph e arquitetura "Human-in-the-Loop".
  • Agent 08: QA, Deploy, manifestos e integridade de pipeline (CI/CD).

Regras Estritas de Implementação

Para consertar a infraestrutura e evitar conflitos:

  • Os agentes executam em "Ondas" (Onda 1: Fundação/Segurança, Onda 2: CRM/IA, Onda 3: Acabamento/UX).
  • A alteração em `schema.prisma` só pode ser feita após handoff para o Agente 01.
  • Nenhuma feature "AI" de prospecção pode contornar os contratos de consentimento LGPD da plataforma.
